## 🎯 Основные возможности

### Управление задачами
- **Реестр задач Управления** - полный контроль всех задач с фильтрацией
- **Мои задачи** - персональный список с приоритизацией по дедлайнам
- **Очередь приемки** - единая очередь для руководителей с задачами на рассмотрении
- **Жизненный цикл**: Новая → В работе → На рассмотрении → На доработке/Принято

### Workflow задач
1. Начальник Управления создает задачу и назначает исполнителя
2. Сотрудник берет задачу в работу
3. После выполнения прикладывает результаты (обязательные вложения) и отправляет на рассмотрение
4. Начальник одобряет (автозакрытие) или возвращает на доработку с комментарием

### Управление проектами
- **Реестр проектов** - все пилотные проекты и партнерские запуски
- **Карточка проекта** - детальная информация, артефакты, статусы
- **Статусы проекта** (фиксированные 1-4):
  1. Реализация платформы
  2. Внутренние тестирования
  3. Согласование условий
  4. Запуск
- **Справки** - быстрая генерация отчетов по проекту

### База исследований R&D
- **Реестр исследований** - каталог завершенных исследований
- **Управление доступом** - передача R&D → IT-проекты
- **Workflow исследований**:
  1. R&D готовит материалы
  2. Начальник Управления одобряет
  3. Открывается доступ второму отделу
  4. IT-проекты используют в своих проектах

### Dashboard
- KPI метрики: просроченные, в работе, на рассмотрении, выполнено в срок
- Статистика по сотрудникам
- Быстрая навигация по фильтрам

## 👥 Роли и права доступа

### Начальник Департамента
- Просмотр всей отчетности и статистики
- Read-only доступ ко всем данным

### Начальник Управления
- Создание и назначение задач
- Приемка/отклонение работ
- Контроль всего портфеля
- Управление доступом к исследованиям

### Начальник отдела
- Распределение задач внутри отдела
- Контроль качества в рамках отдела
- Эскалация на Начальника Управления

### Сотрудник
- Выполнение назначенных задач
- Подготовка результатов и артефактов
- Работа с исследованиями (R&D) или проектами (IT)

## 🔑 Ключевые особенности

### Обязательные артефакты
- Нельзя отправить задачу на рассмотрение без вложений
- Валидация наличия результатов перед отправкой
- Все файлы с метаданными (размер, дата, автор)

### Контроль дедлайнов
- Визуальные индикаторы просрочки
- Группировка по срочности: сегодня, скоро, позже
- Нет тайм-трекинга - только дедлайны и напоминания

### Прозрачность процессов
- Полная история изменений по каждому объекту
- Комментарии с причинами возврата
- Статусы с цветовой индикацией

### Межотдельная передача
- Контролируемый доступ R&D → IT-проекты
- Уровни доступа: только чтение / копирование в проект
- Связь исследований с проектами

## 📊 Основные сценарии

### S1: Постановка и приемка задачи
1. Начальник создает задачу и назначает сотрудника
2. Сотрудник берет в работу
3. Прикладывает результаты и отправляет на рассмотрение
4. Начальник одобряет → задача закрывается автоматически

### S2: Возврат на доработку
1. Исполнитель отправил на рассмотрение
2. Начальник вернул с комментарием (обязательно)
3. Исполнитель исправляет и отправляет повторно
4. Начальник одобряет

### S3: Контроль портфеля
1. Начальник открывает реестр задач
2. Применяет фильтры (отдел, статус, просрочка)
3. Просматривает статистику
4. Переходит в карточки задач

### S4: Управление проектом
1. Создание проекта
2. Ведение статусов 1→2→3→4
3. Прикрепление артефактов
4. Формирование справки

### S5: Передача R&D → IT-проекты
1. R&D завершает исследование
2. Начальник Управления принимает
3. Открывает доступ IT-проектам
4. IT использует материалы в новых проектах

## 🔐 Управление доступом

### Принципы RBAC
- Прозрачность ограничений (подсказки "Недостаточно прав")
- Наследование доступа по отделам
- Read-only для просмотра чужих объектов

### Проверка прав
```typescript
// Начальник Управления - полный доступ
// Начальник отдела - в своем отделе
// Сотрудник - только свои задачи
canUserEdit(currentUser, itemCreatorId, itemDivision)
```
